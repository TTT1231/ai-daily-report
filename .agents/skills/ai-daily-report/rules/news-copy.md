# 成品新闻文案：把事实讲给观众听

适用于所有生产模式的标题、`tabs[].summary` 和 `scenes[].subtitle`。事实台账保存出处和核验过程；成品文案根据这些事实重新组织讲述，不沿用摘录笔记的句式。原生 RSS 模型的对应要求维护在 `ingest/prompts.go`。

## 写稿顺序：从事实到讲述

在写 `data.json` 前完成以下写作过程；在当前生成环节内完成，不新增模型调用、台账或固定数量的 Scene：

1. **理解事件**：从来源中提炼「主体、动作或变化、结果、必要条件」，分清哪部分是事实，哪部分是来源身份、原文位置或取证过程。沿用已有事实台账：`statement` 写完整事实命题，`source` / `excerpt` 保存出处与定位，`qualifiers` 保存不可删的条件。只有图内标签时先弄清标签与结果的关系；无法确定的关系不补写。
2. **先写整条口播**：面向没读过来源的观众，把核心事件及有新闻价值的事实连贯讲清。由事实关系决定开头和承接，不按网页段落、截图顺序或 Tab 顺序逐项转述；不从「这份资料写了什么」起句，再靠替换词语润色。
3. **再整理展示内容**：按完整口播的事实关系分成 Scene，按有价值的独立事实组织 Tabs，匹配能证明各段的图片。Tabs 可以保留有依据的补充信息，不逐字复制口播；标题承诺的核心必须在口播中解释。
4. **对照复核后写入 Raw**：连读口播，确认新闻本身是叙述中心，听众无需自行读图才能理解；再对照台账和原始选题，核对归因、事实强度、数字与条件。仍像资料摘录时回到第 2 步重写对应段落，不以命中词已删掉、结构校验通过作为完成标准。

## 先确定这句话在讲什么

- **事件**：谁做了什么，发生了什么变化。例如「应用只对创建者本人可见、可安装」，而非「页面说明应用……」。发布、接入、调整、开放、限制等动作必须有来源支持。
- **评测**：在谁的什么评测中，哪个对象取得什么结果，比较对象和成立条件是什么。先说评测，再说成绩；不用「问答图表中」「基准图显示」串起数字。厂商自测保留「在自家测试中」；单项成绩不能扩成整体能力领先。
- **规则与期限**：直接讲适用对象、规则和有效时间。例如「额度提高至 100 美元，活动截至 10 月 16 日」，而非「帖子给出的截止日是……」。只有来源已确认的绝对日期才这样写；原帖的「未来三天」不能直接变成播出日起的未来三天，也不能擅自换算截止日期。
- **观点、预测、争议或观察**：把责任留给发言者，例如「Anthropic 预计……」「据某机构监测……」「自称攻击者声称……」。自然口吻不能把预测、单方说法或观察变成已确认事实。

这不是把「图表」替换成「评测」、把「列出」替换成「已接入」的词语替换题。先判断证据实际支持的是成绩、排名、目录变化还是可用状态，再写对应的事实关系。来源只证明加入目录，就说「将某模型加入目录」；只有确认能调用时，才说「已支持使用」。榜单的排名或更新、文档的修改、账号的发言本身是新闻时，可以直接讲这些事件。

## 从资料摘录到主持人口吻

下面沿用问题稿的事实作写法示例，不是新一期可以照搬的新闻；使用时仍须对照当次来源。省略号表示此处只演示句式，成稿要写完整。

| 资料摘录式写法 | 成品写法 |
| --- | --- |
| Google 的 ERQA 机器人相关问答图表中，Gemini 4 Argon 得 87%；测试标注 Tool off、N=400。 | 在 Google 的 ERQA 评测中，Gemini 4 Argon 得分为 87%。测试未启用工具，样本量为 400。 |
| SimpleQA Verified 榜单中，Argon 为……，GPT-6 Astra 为…… | 在 SimpleQA Verified 评测中，Argon 和 GPT-6 Astra 的得分分别为……。接着保留各自误差范围及比较结论，不能把误差区间重叠说成明确领先。 |
| OpenCode Go 已列出 Gemini 4 Argon Contributor；文档提示，提示词与回答可能被用于训练未来 Google 模型。 | OpenCode Go 将 Gemini 4 Argon Contributor 加入模型目录。使用该选项时，提示词和回答可能用于训练未来的 Google 模型。 |
| 页面说明应用仅创建者本人可见并能安装。 | 这些应用仅创建者本人可见、可安装。 |
| Command Code 官方账号称，活动额度提高至 100 美元；帖子给出的截止日是 10 月 16 日。 | Command Code 将活动额度提高至 100 美元，活动截至 10 月 16 日。实际成稿还须写明适用模型。 |
| Anthropic 的基准图显示，开发环境拉取最新代码从 87 秒降至 3.5 秒。 | 在 Anthropic 自家的测试中，新系统将开发环境拉取最新代码的用时从 Git 的 87 秒缩短到 3.5 秒。 |

Tabs 同样写完整事实句，不能把读图腔留在摘要里。口播去掉 Markdown，通用测试标签转成自然中文，如「未启用工具」「样本量为 400」；必要产品名、版本号、单位、误差和测试条件保留。不要只念数值，让观众猜它是在测什么；任务含义只在来源支持时解释，不能按缩写猜测。

## 出处归因与口播节奏

同一 Story 在需要交代可信度时说明一次来源身份，后续用自然衔接；更换数据提供方、进入预测或未经证实的说法时重新明确归因。公司宣布自己的产品调整可直接说公司做了什么；公司对性能的自测、媒体独家报道、用户实测、指控与预测仍保留相应归因。不能为了顺口，把「可能用于训练」「仅创建者可用」「关闭工具的测试」等条件删掉。

一条新闻围绕事件展开，后句接着解释前句中的对象。少用分号把产品接入、基准得分、折扣和条款挤成一长串；按事实关系拆句或分段。既不让每句都从「页面、帖子、文档、图表」重新开始，也不靠「重磅、炸裂、这意味着」增加没有依据的情绪或结论。

## 成稿自查

把一条 Story 的 subtitle 连起来，只听声音检查：是否先知道事件，再理解结果与必要条件；句子是否像在直接讲新闻，还是不断提醒观众「资料里写了什么」。随后用同样标准检查每张 Tab，并对照事实台账确认主张强度、归因、日期、数值和条件没有变化。

这项检查并入已有成稿审查，不另增一轮取证。`--strict-tone` 只能发现常见句式，不能证明文案自然或事实正确；命中时重写整句并对照来源，不自动删除命中的词。
